## 独立站最小功能（MVP）

建议优先审计并复用现有私有仓库 dev-bar（Next.js、React、Tailwind），而不是从零建立新技术栈。dev-bar 现有“杭州线下”“100% 私密”“终身免费”等文案未经当前商业验证，**不得原样上线**。

### 页面

1. 首页：软件、AI、IoT、系统集成主定位、客户常见问题、案例入口。
2. 服务中心：12 大领域、具体服务及编号、标准套餐/定制/专项评估标签、参考价格。
3. 案例：有权展示、可核验的源码/演示/版本/测试与限制说明。
4. 定价：小型服务套餐 + 技术诊断/PoC/开发/维护的收费逻辑。
5. 需求咨询：可提交文字需求与联系方式，暂不直接收明文密码、生产库备份。
6. 关于、联系方式、服务条款、隐私政策、AI 辅助交付政策。

### 线索表单建议字段

必要：服务分类、需求标题、简述、联系邮箱或联系方式（二选一）、授权确认。可选：系统/版本、预算范围、期望日期、敏感数据约束、附件（建议 MVP 不支持直接上传敏感源码）。

## 统一询盘流程

自然流量/独立站/平台/推荐 → 渠道归属 → 线索编号 → 人工预审（范围、权限、风险、资源） → 选择标准套餐 / 付费诊断 / 定制 PoC → 书面报价与合同（平台订单按平台规则） → 开发、测试、部署 → 验收 → 售后。

内部字段建议：lead_id、source_channel、source_reference、service_id、lead_status、scope_summary、risk_level、ai_data_permission、quote_id、assigned_owner、created_at、updated_at。客户数据保留最少且可删除；**GitHub 仓库不直接存客户原始隐私/源码/明文密钥**。

## 技术与安全

- 服务端校验、限流、防垃圾提交；后台访问控制；HTTPS；异常与告警；通知失败可重试。
- 仅授权人员能读询盘；去标识化统计订单来源、咨询率、付费率和交付成本。
- 先上线“提交需求/预约”，支付和正式合同能力根据真实主体、合规和风险逐步建设。
- 内地服务器对外建站通常需要相应 ICP 备案；部署地域、域名、运营主体和许可需核查。
- 收集联系资料要有隐私告知、最小必要原则和删除/保留流程。
- 第三方外包平台的订单仍在对应平台完成付款和履约，不设计违法违规绕站功能。
