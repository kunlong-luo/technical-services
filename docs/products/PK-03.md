## 3. 包含的事项

- 安装或配置合法来源的约定开发工具与依赖
- Node.js 项目优先使用 pnpm；Java/Python 分别按项目要求安装配套工具
- 记录工具版本、PATH 或环境变量，并用 Hello World 或双方指定的最小项目验证

## 4. 不包含事项

- 电脑操作系统重装、磁盘分区、数据迁移
- 企业私有仓库的复杂构建故障、历史项目无限兼容
- GPU 驱动、AI 大模型下载、远程公司内网/代理服务的违规配置

## 5. 客户下单前需要提供什么？

- Windows/Linux 版本、处理器、内存、硬盘空间与网络条件
- 想开发的语言、IDE、项目版本或最低要求
- 允许安装的软件清单、管理员授权与备份确认

## 6. 如何验收？

- 约定工具显示正确版本号
- 最小样例能够在约定命令/IDE 中成功运行
- 交付简单操作指南与环境清单；出现硬件或权限限制要如实记录

正式交付以双方确认的范围、设备/浏览器与环境、测试结果为准；未知限制须在实施前告知，不能用 AI 生成内容替代验收记录。

## 7.1 标准接单与交付流程（文档草案）

1. **咨询预检**：下单前询问 OS/版本、CPU/内存/剩余空间、网络/权限、期望语言与准确版本、IDE、是否有已有冲突版本、当前报错；只收必要技术信息，不收密码或私有源码。
2. **明确报价与边界**：在平台允许的交易流程内确认设备数、技术栈数、目标 IDE 和最小验收命令、工作窗口、费用及若失败/中断如何处理；超范围先取得客户同意，不擅自加价。
3. **授权和保护**：客户自行授权远程访问、检查资料与备份；谨慎处理 PATH、多版本 SDK、代理、企业策略，不做破坏性系统调整。密码由客户在本机输入。
4. **执行与记录**：仅从合法来源安装/配置约定工具，记录每步版本、安装来源、设置变更和遇到的限制；必要时先备份配置，提前说明回退方法。
5. **验收与交接**：由客户在其设备上看到约定版本、示例实际运行、重开终端仍可用；交付《环境清单+操作说明+问题/回退记录》，双方在平台内确认结果。
6. **售后/退款**：只针对所约定范围协商处理，正式取消/退款以实际适用平台规则和双方合法约定为准；不预设“虚拟服务不退”。

**适用边界：** “IDE 打开既有企业项目”不自动等于“修复项目历史依赖或全部业务 BUG”；数据库、Docker、GPU 等必须在套餐中明确写出实际验收条件。
